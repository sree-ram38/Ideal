Chapter 01 — Foundations

What is AJAX?

Understand the big idea — the problem AJAX solves and why every modern website uses it.

The problem before AJAX

Imagine you're on an e-commerce site in the early 2000s. You click "Add to cart". The entire page reloads — all the HTML, CSS, images, everything downloads again. Just to update one tiny cart icon. That was the web before AJAX.

Real-world analogy

Old web (no AJAX): Every time you want the bill at a restaurant, they destroy the whole restaurant, rebuild it from scratch, and hand you the bill.

Web with AJAX: The waiter quietly walks to the kitchen, gets just the bill, and brings it to your table. You never had to move.

What AJAX stands for
A — Asynchronous
Happens in the background. Doesn't freeze or block the page. User can keep clicking, scrolling, typing.
J — JavaScript
The programming language that makes the request happen, processes the response, and updates the page.
A — And
Just a conjunction in the name.
X — XML (now JSON)
Originally used XML for data. Today virtually all APIs use JSON instead. The name is historical.
AJAX in the wild — sites you use every day
Google Search autocomplete
Every keystroke fires an AJAX request. Results appear instantly without any page reload.
Instagram / Twitter feed
Infinite scroll loads more posts via AJAX as you scroll — silently, in the background.
Form validation
"Email already taken" — checked live via AJAX before you even click submit.
Gmail / Outlook
New emails appear without refreshing. Sending mail, starring, archiving — all AJAX.
AJAX vs. Full page reload — side by side
AspectFull page reloadAJAX
Data transferredEntire HTML page (100KB+)Just the needed data (1-5KB)
User experiencePage flickers, scroll resetsSeamless, no interruption
SpeedSlow (rebuild everything)Fast (update only what changed)
Server loadHigh (full page every time)Low (small data responses)

Chapter 02 — Foundations

How AJAX works

The full lifecycle of an AJAX request — from user action to DOM update. Plus: what "asynchronous" actually means.

The 4-step lifecycle
1
User triggers an eventA click, keypress, scroll, timer, form submit — anything that starts the process.
2
JavaScript sends an HTTP requestUsing XHR or fetch(), JS sends a request to a server URL. This happens in the background — the page doesn't freeze.
3
Server processes and respondsThe server runs logic (queries a database, etc.) and sends back data — usually as JSON text.
4
JavaScript updates the DOMYour callback/promise fires. You parse the response and update only the part of the page that needs to change.
What does "asynchronous" really mean?
Synchronous (blocking)
Code runs line by line. Line 2 cannot run until line 1 finishes. If line 1 is "wait 3 seconds for network", the whole page freezes for 3 seconds. That's a terrible experience.
Asynchronous (non-blocking)
Line 1 fires a request and immediately moves on. The page stays responsive. When the server responds — 200ms later — a callback or promise picks up the result and continues.
Analogy — ordering at a restaurant

Synchronous: You give your order and stand frozen at the counter until the food is ready. No one else can order. You don't move. Everything stops.

Asynchronous: You give your order and go sit down. The waiter takes other orders. Your phone can ring. When the food is ready, the waiter brings it to you. Nothing blocked.

JavaScript's event loop — the engine behind async

JavaScript runs on a single thread — it can only do one thing at a time. Yet it handles many async operations simultaneously. How? The event loop.

→
Call StackWhere your synchronous code runs. One operation at a time.
→
Web APIsBrowser handles async work (network requests, timers). JS doesn't wait — it delegates and moves on.
→
Callback QueueWhen async work finishes, the callback is placed here, waiting.
→
Event LoopChecks: is the call stack empty? If yes, push the next callback from the queue onto the stack to run.
💡Key insight: Your AJAX callback doesn't interrupt whatever JS is running. It patiently waits in the queue and runs when the stack is clear. This is why JS can seem to do many things "at once" on a single thread.
HTTP methods you'll use in AJAX
GET
Fetch / read data. "Give me the list of products." No body. Data goes in the URL. Most common.
POST
Create new data. "Save this new user." Sends data in request body as JSON.
PUT / PATCH
Update existing data. PUT = replace whole resource. PATCH = update only specific fields.
DELETE
Remove a resource. "Delete product with ID 42." Usually no body.
A user clicks a "Like" button. The like count updates instantly without any page flicker. Which step does the browser do LAST?

Chapter 03 — Foundations

HTTP & JSON

The two languages AJAX speaks: HTTP for communication, JSON for data. Master these and APIs become easy.

HTTP status codes — what the server is saying

Every AJAX response includes a status code. Your code needs to check this to know if the request succeeded or failed.

200
OK
Request succeeded. Data is in the response body.
201
Created
POST succeeded. New resource was created.
204
No Content
Success, but no data returned (common for DELETE).
400
Bad Request
You sent invalid/malformed data. Fix your request.
401
Unauthorized
Need to log in / provide auth token first.
403
Forbidden
Logged in but don't have permission.
404
Not Found
That URL or resource doesn't exist.
429
Too Many Requests
You're being rate limited. Slow down!
500
Server Error
Something broke on the server side. Not your fault.
503
Service Unavailable
Server is down/overloaded. Try again later.
⚠️Critical: fetch() does NOT throw an error for 4xx/5xx responses. It only rejects for network failures. You must manually check response.ok or response.status. This trips up almost every beginner.
JSON — the universal data format

JSON (JavaScript Object Notation) is plain text that looks like a JavaScript object. Every modern API returns JSON. You need two methods to work with it:

JSON.parse(string)
Converts a JSON string (what the server sends) into a real JavaScript object. Use after receiving a response.
JSON.stringify(object)
Converts a JavaScript object into a JSON string. Use before sending data to a server in a request body.
json-basics.js
// Server sends this as plain text (a JSON string)
const serverResponse = '{"id":1,"name":"Priya","city":"Chennai","active":true}';

// Step 1: Parse the string into a real JS object
const user = JSON.parse(serverResponse);
console.log(user.name);    // Priya
console.log(user.city);    // Chennai
console.log(user.active);  // true
console.log(typeof user);  // object

// Step 2: Convert JS object to string (for sending to server)
const newUser = { name: "Arjun", age: 24, skills: ["JS", "CSS"] };
const jsonString = JSON.stringify(newUser);
console.log(jsonString);
console.log(typeof jsonString); // string
What JSON looks like
example-api-response.json
{
  "id": 42,
  "name": "Priya Sharma",
  "email": "priya@example.com",
  "active": true,
  "scores": [95, 87, 91],
  "address": {
    "city": "Chennai",
    "zip": "600001"
  }
}
ℹ️JSON rules: Keys must be in double quotes. No trailing commas. No comments. Values can be string, number, boolean, null, array, or object.
CORS — why your request might be blocked
What is CORS?
Cross-Origin Resource Sharing. Browsers block requests from site-a.com to api.site-b.com unless the API server explicitly allows it. This is a browser security feature, not a JavaScript feature.
You see this error
Access to fetch at 'https://api.example.com' from origin 'http://localhost:3000' has been blocked by CORS policy
How to fix it
If you own the API: add Access-Control-Allow-Origin headers. If not: proxy via your own backend, or use a CORS-friendly API.
⚠️CORS is enforced by the browser only. Postman, curl, and Node.js never get CORS errors. That's why requests work in Postman but fail in your browser.

Chapter 04 — Core APIs

XMLHttpRequest

The original AJAX API. Verbose but foundational. Understanding XHR makes everything else click.

ℹ️XHR was introduced in 2000. Modern code uses fetch() instead, but XHR is everywhere in existing codebases. You must understand it.
XHR GET request — step by step
xhr-get.js
// Step 1: Create an XHR object
const xhr = new XMLHttpRequest();

// Step 2: Configure — method and URL
xhr.open('GET', 'https://jsonplaceholder.typicode.com/users/1');

// Step 3: Define what to do when response arrives
xhr.onload = function() {
  if (xhr.status === 200) {
    const user = JSON.parse(xhr.responseText);
    console.log('Name:', user.name);
    console.log('Email:', user.email);
    console.log('City:', user.address.city);
  } else {
    console.log('Error: status', xhr.status);
  }
};

// Step 4: Handle network errors
xhr.onerror = function() {
  console.log('Network error!');
};

// Step 5: Send the request
xhr.send();
XHR POST — sending data
xhr-post.js
const xhr = new XMLHttpRequest();
xhr.open('POST', 'https://jsonplaceholder.typicode.com/posts');

// IMPORTANT: tell server you're sending JSON
xhr.setRequestHeader('Content-Type', 'application/json');

xhr.onload = function() {
  const result = JSON.parse(xhr.responseText);
  console.log('Created! New ID:', result.id);
  console.log('Title:', result.title);
};

// Stringify object → send in body
xhr.send(JSON.stringify({
  title: 'My first AJAX post',
  body: 'Learning XHR is important!',
  userId: 1
}));
XHR ready states
readyState 0
UNSENT — object created, open() not called
readyState 1
OPENED — open() called, request configured
readyState 2
HEADERS_RECEIVED — server responded, headers in
readyState 3
LOADING — body being downloaded
readyState 4
DONE — complete. Read responseText now.

FeatureXHRfetch()

JSONManual JSON.parse requiredresponse.json() built in
Browser supportAll browsers including IEAll modern browsers
Chaining requestsCallback hellClean with async/await

Chapter 05 — Core APIs

The fetch() API

The modern standard. Promise-based, clean, and powerful. This is what you'll use in 95% of real projects.

Basic GET with fetch
fetch-get.js
fetch('https://jsonplaceholder.typicode.com/posts/1')
  .then(response => {
    // response.ok = true if status is 200-299
    if (!response.ok) {
      throw new Error('HTTP error: ' + response.status);
    }
    return response.json(); // Parse JSON body
  })
  .then(post => {
    console.log('Title:', post.title);
    console.log('Body:', post.body.slice(0,60) + '...');
  })
  .catch(error => {
    console.log('Error:', error.message);
  });
POST — sending data
fetch-post.js
fetch('https://jsonplaceholder.typicode.com/posts', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    title: 'Learning fetch()',
    body: 'Much cleaner than XHR!',
    userId: 1
  })
})
  .then(res => res.json())
  .then(data => {
    console.log('Created! ID:', data.id);
    console.log('Title:', data.title);
  });
PUT — updating existing data
fetch-put.js
fetch('https://jsonplaceholder.typicode.com/posts/1', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    id: 1,
    title: 'Updated title',
    body: 'Updated body text',
    userId: 1
  })
})
  .then(res => res.json())
  .then(data => console.log('Updated:', data.title));
DELETE — removing data
fetch-delete.js
fetch('https://jsonplaceholder.typicode.com/posts/1', {
  method: 'DELETE'
})
  .then(res => {
    // 200 means deleted successfully
    console.log('Deleted! Status:', res.status);
  });
⚠️Big gotcha: fetch() only rejects (goes to .catch) for network failures — no internet, DNS errors, etc. A 404 or 500 response still resolves! You MUST check response.ok to detect server errors.

Chapter 06 — Core APIs

async / await

Write async code that reads like normal code. The cleanest way to work with fetch() and Promises.

The problem with promise chains

When you need to make multiple requests that depend on each other, .then() chains get deeply nested and hard to read. async/await solves this.

Promise chains (messy)
getUser(1)
  .then(user => {
    return getPosts(user.id)
      .then(posts => {
        return getComments(
          posts[0].id
        ).then(comments => {
          // 4 levels deep!
        });
      });
  });
async/await (clean)
async function load() {
  const user = await getUser(1);
  const posts = await getPosts(user.id);
  const comments = await getComments(
    posts[0].id
  );
  // Flat! Much easier to read
}
async/await with fetch — the full pattern
async-await.js
// async keyword makes function return a Promise
async function fetchUser(id) {
  try {
    // await pauses HERE until fetch resolves
    const response = await fetch(
      `https://jsonplaceholder.typicode.com/users/${id}`
    );

    if (!response.ok) {
      throw new Error('User not found: ' + response.status);
    }

    // await pauses again until JSON is parsed
    const user = await response.json();

    console.log('Name:', user.name);
    console.log('Email:', user.email);
    console.log('Company:', user.company.name);
    console.log('City:', user.address.city);
    return user;

  } catch (error) {
    // Catches BOTH network errors AND our thrown errors
    console.log('Error:', error.message);
  }
}

fetchUser(3);
Parallel requests — Promise.all()

When requests don't depend on each other, run them simultaneously. awaiting each one in sequence makes them run one-after-another, which is slow.

promise-all.js
async function loadDashboard() {
  console.log('Firing all 3 requests simultaneously...');

  // All 3 requests fire AT THE SAME TIME
  const [usersRes, postsRes, todosRes] = await Promise.all([
    fetch('https://jsonplaceholder.typicode.com/users?_limit=3'),
    fetch('https://jsonplaceholder.typicode.com/posts?_limit=3'),
    fetch('https://jsonplaceholder.typicode.com/todos?_limit=3')
  ]);

  const [users, posts, todos] = await Promise.all([
    usersRes.json(),
    postsRes.json(),
    todosRes.json()
  ]);

  console.log('Users:', users.length, '| first:', users[0].name);
  console.log('Posts:', posts.length, '| first:', posts[0].title.slice(0,30));
  console.log('Todos:', todos.length, '| first:', todos[0].title.slice(0,30));
}

loadDashboard();
💡Rule of thumb: If request B needs data from request A → sequential awaits. If A, B, C are independent → Promise.all(). Sequential is safe. Promise.all is fast.

Chapter 07 — Advanced

Error handling

Production AJAX must handle every failure gracefully. Networks fail, servers crash, users have bad internet. Your code must be ready.

The 3 types of failures you must handle
Network error
No internet connection, DNS failure, server unreachable. fetch() rejects its Promise. Caught by .catch() or try/catch.
HTTP error (4xx / 5xx)
Server responded, but with an error code. fetch() resolves! You must check response.ok or response.status yourself.
Parse error
Server returned malformed JSON. response.json() rejects. Wrap in try/catch to handle.
Complete error handling pattern
error-handling.js
async function safeFetch(url) {
  try {
    const response = await fetch(url);

    // Handle HTTP errors manually (fetch doesn't throw!)
    if (!response.ok) {
      const status = response.status;
      if (status === 404) throw new Error('Not found (404)');
      if (status === 401) throw new Error('Unauthorized. Log in first.');
      if (status === 500) throw new Error('Server crashed (500)');
      throw new Error('HTTP Error: ' + status);
    }

    const data = await response.json();
    console.log('Success:', data.name || data.title);
    return data;

  } catch (error) {
    if (error instanceof TypeError) {
      console.log('Network error — no internet?');
    } else {
      console.log('Error:', error.message);
    }
  }
}

// Try a 404 URL
safeFetch('https://jsonplaceholder.typicode.com/posts/99999');
Loading / error / success UI states

Every real AJAX call needs 3 UI states. Never leave the user staring at nothing.

ui-states.js
async function loadData() {
  // 1. LOADING state — show spinner, hide previous results
  document.getElementById('spinner').style.display = 'block';
  document.getElementById('content').style.display = 'none';
  document.getElementById('error').style.display = 'none';

  try {
    const res = await fetch('/api/data');
    if (!res.ok) throw new Error('Server error: ' + res.status);
    const data = await res.json();

    // 2. SUCCESS state — hide spinner, show data
    document.getElementById('spinner').style.display = 'none';
    document.getElementById('content').innerHTML = renderData(data);
    document.getElementById('content').style.display = 'block';

  } catch (err) {
    // 3. ERROR state — hide spinner, show error message
    document.getElementById('spinner').style.display = 'none';
    document.getElementById('error').textContent = err.message;
    document.getElementById('error').style.display = 'block';
  }
}
Retry with exponential backoff
retry.js
async function fetchWithRetry(url, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      const res = await fetch(url);
      if (!res.ok) throw new Error('Status: ' + res.status);
      const data = await res.json();
      console.log('Success on attempt', attempt + 1);
      return data;

    } catch (err) {
      const isLast = attempt === maxRetries - 1;
      if (isLast) throw err; // Give up

      // Exponential backoff: 500ms, 1s, 2s...
      const wait = 500 * Math.pow(2, attempt);
      console.log(`Attempt ${attempt+1} failed. Retrying in ${wait}ms...`);
      await new Promise(r => setTimeout(r, wait));
    }
  }
}

fetchWithRetry('https://jsonplaceholder.typicode.com/users/2')
  .then(u => console.log('Got user:', u.name))
  .catch(e => console.log('All retries failed:', e.message));

Chapter 08 — Advanced

Real-world patterns

AbortController, debounce, request caching, and Axios. The patterns used in production apps.

AbortController — cancel stale requests

When a user types in a search box, a new request fires every keystroke. If the 1st request responds after the 5th, you show stale data. AbortController cancels the old one before firing a new one.

abort-controller.js
let controller = null;

async function search(query) {
  // Cancel the previous in-flight request
  if (controller) {
    controller.abort();
    console.log('Cancelled previous request');
  }

  controller = new AbortController();

  try {
    const res = await fetch(
      `https://jsonplaceholder.typicode.com/posts?_limit=2`,
      { signal: controller.signal }  // link to controller
    );
    const data = await res.json();
    console.log(`"${query}" → got ${data.length} results`);

  } catch (err) {
    if (err.name === 'AbortError') {
      console.log(`"${query}" request aborted`);
    }
  }
}

// Simulate rapid user typing: only last one completes
search('j');
search('ja');
search('jav');
search('java');
Debounce — don't fire on every keystroke

Debouncing delays the request until the user stops typing for a set amount of time (e.g. 300ms). Prevents sending 10 requests for "javascript".

debounce.js
// Utility function — reusable for any async task
function debounce(fn, delay) {
  let timer;
  return function(...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

// Your actual search function
async function searchAPI(query) {
  if (!query.trim()) return;
  const res = await fetch(`/api/search?q=${query}`);
  const data = await res.json();
  renderResults(data);
}

// Fires ONLY 300ms after typing stops
const debouncedSearch = debounce(searchAPI, 300);

// Attach to input event
searchInput.addEventListener('input', (e) => {
  debouncedSearch(e.target.value);
});
Simple request cache
cache.js
const cache = new Map();

async function cachedFetch(url) {
  if (cache.has(url)) {
    console.log('Cache HIT for:', url.split('/').pop());
    return cache.get(url);
  }

  console.log('Cache MISS — fetching...');
  const res = await fetch(url);
  const data = await res.json();
  cache.set(url, data);
  return data;
}

// First call — fetches from network
const u1 = await cachedFetch('https://jsonplaceholder.typicode.com/users/1');
console.log('Got:', u1.name);

// Second call — returns from cache instantly
const u2 = await cachedFetch('https://jsonplaceholder.typicode.com/users/1');
console.log('Got again:', u2.name);
Axios — the most popular AJAX library
Auto JSON parsing
No res.json() needed. Response data is in response.data directly.
Throws on HTTP errors
Unlike fetch(), Axios automatically throws for 4xx/5xx. Simplifies error handling.
Interceptors
Run code before every request (add auth header) or after every response (log errors).
Base URL & defaults
Create an instance with a base URL and headers once. Every call inherits them.
axios-patterns.js
// npm install axios
import axios from 'axios';

// Create a reusable instance
const api = axios.create({
  baseURL: 'https://api.myapp.com',
  timeout: 5000,
  headers: { 'Authorization': `Bearer ${token}` }
});

// GET — auto-parses JSON, data is in .data
const { data: users } = await api.get('/users');

// POST — no need to stringify body
await api.post('/users', { name: 'Priya', email: 'priya@x.com' });

// Interceptor — add auth token to every request
api.interceptors.request.use(config => {
  config.headers.Authorization = `Bearer ${getToken()}`;
  return config;
});

// Interceptor — handle all errors globally
api.interceptors.response.use(
  response => response,
  error => {
    if (error.response.status === 401) redirectToLogin();
    return Promise.reject(error);
  }
);
