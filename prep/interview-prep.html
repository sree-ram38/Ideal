Q1 What is Django and why is it used? Django ▼

Django is a high-level Python web framework that follows the MTV (Model-Template-View) architectural pattern. It is used because it comes "batteries included" — meaning it provides built-in solutions for authentication, ORM, admin panel, form handling, security, and URL routing without needing third-party libraries.

  • Rapid development — built-in admin, auth, ORM saves weeks of work
  • Security — CSRF protection, SQL injection prevention, XSS protection built-in
  • Scalable — used by Instagram, Pinterest, Disqus at massive scale
  • DRY principle — Don't Repeat Yourself; encourages reusable components
Interview tip: Mention "batteries included" and name 3 built-in features (ORM, admin, auth). Interviewers love this phrase.

Q3 What is Django's ORM? How does it work? Django ▼

ORM stands for Object-Relational Mapper. It lets you interact with your database using Python objects instead of writing raw SQL. Each model class maps to a database table; each instance maps to a row.

orm_example.py
# Instead of: SELECT * FROM posts WHERE status='published' ORDER BY -created
posts = Post.objects.filter(status='published').order_by('-created')

# Create a record
post = Post.objects.create(title='Hello', author=user)

# Update
Post.objects.filter(id=1).update(status='published')

# Delete
Post.objects.filter(status='draft').delete()
Key point: QuerySets are lazy — the database is not queried until you actually iterate the results or call list(), len(), or similar.

Q4 What are Django migrations? Why are they important? Django ▼

Migrations are Django's way of propagating model changes to the database schema. They are Python files that contain instructions to create, alter, or delete database tables and columns.

terminal
# Step 1: Detect model changes, create migration file
python manage.py makemigrations

# Step 2: Apply migrations to the database
python manage.py migrate

# Show migration status
python manage.py showmigrations

# Rollback to a specific migration
python manage.py migrate app_name 0002
Important: Always commit migration files to version control. Never delete migration files from a deployed app — it breaks the migration history.

Q6 What is Django's settings.py and what are the most important settings? Django ▼

settings.py is the central configuration file for a Django project. Key settings include:

  • SECRET_KEY — cryptographic key; must be secret in production (use env vars)
  • DEBUG — True in dev, False in production (never True in production!)
  • ALLOWED_HOSTS — list of domain names that can serve this app
  • INSTALLED_APPS — list of all active apps including third-party
  • DATABASES — database connection config
  • MIDDLEWARE — list of middleware classes (order matters!)
  • STATIC_URL / MEDIA_URL — for serving static files and user uploads
Security: Never hardcode SECRET_KEY or DB passwords. Use environment variables with python-dotenv or os.environ.

Q8 What is Django middleware? Give examples. Django ▼

Middleware is a framework of hooks into Django's request/response processing. It's a layer that processes requests before they reach the view and responses before they reach the client.

  • SecurityMiddleware — adds security headers, redirects HTTP to HTTPS
  • SessionMiddleware — manages user sessions across requests
  • AuthenticationMiddleware — attaches request.user to every request
  • CsrfViewMiddleware — verifies CSRF token on POST requests
  • CorsMiddleware — handles CORS headers (from django-cors-headers)
Order matters: Middleware is processed top-to-bottom for requests and bottom-to-top for responses. CorsMiddleware must be first in the list.

Q9 What are Django signals? When would you use them? Django ▼

Signals allow decoupled applications to get notified when certain actions occur. They implement the Observer pattern — senders broadcast signals, receivers listen and react.

signals.py
from django.db.models.signals import post_save
from django.dispatch import receiver
from .models import User, Profile

@receiver(post_save, sender=User)
def create_user_profile(sender, instance, created, **kwargs):
    if created:
        Profile.objects.create(user=instance)
        # Send welcome email, etc.

Common signals: pre_save, post_save, pre_delete, post_delete, m2m_changed.

Q15 What is CSRF and how does Django handle it? Django ▼

CSRF (Cross-Site Request Forgery) is an attack where a malicious website tricks a user's browser into making unauthorized requests to your app. Django prevents it by generating a unique CSRF token per session and requiring it on every non-GET request.

template.html + ajax
<!-- In templates -->
{% csrf_token %}

// In AJAX requests
function getCsrf() {
  return document.cookie.split(';')
    .find(c => c.trim().startsWith('csrftoken='))
    ?.split('=')[1];
}
headers: { 'X-CSRFToken': getCsrf() }

Q16 What is the N+1 query problem and how do you solve it in Django? Django ▼

The N+1 problem occurs when you execute 1 query to get N objects, then execute N additional queries to get related data for each object. For example: fetching 20 posts and then accessing post.author in a loop — that's 21 queries instead of 1.

n_plus_one_fix.py
# BAD — N+1 problem: 1 + 20 queries
posts = Post.objects.all()
for post in posts:
    print(post.author.name)  # separate DB hit each time!

# GOOD — select_related: single JOIN query (for ForeignKey)
posts = Post.objects.select_related('author', 'category').all()

# GOOD — prefetch_related: 2 queries total (for ManyToMany/reverse FK)
posts = Post.objects.prefetch_related('tags', 'comments').all()
Critical: Install Django Debug Toolbar in development. It shows you every SQL query. N+1 is the #1 performance killer in Django apps.

Q19 How does Django caching work? What are the cache backends? Django ▼

Django supports multiple cache backends. Caching avoids repeated expensive DB queries or computation.

  • LocMemCache — in-process memory (default, not shared across processes)
  • RedisCache — Redis server (best for production, shared across workers)
  • MemcachedCache — Memcached (older alternative to Redis)
  • DatabaseCache — stores cache in DB table (easy setup, slower)

from django.views.decorators.cache import cache_page

Q20 What is transaction.atomic() and why is it important? Django ▼

transaction.atomic() wraps database operations in a single transaction. If any operation inside raises an exception, all changes are rolled back — none of the partial changes remain.

transactions.py
from django.db import transaction

# If payment.save() fails, order.save() is also rolled back
with transaction.atomic():
    order = Order.objects.create(user=user, total=amount)
    Payment.objects.create(order=order, status='paid')
    Inventory.objects.filter(product=product).update(
        quantity=F('quantity') - 1
    )
Use this for: any operation that involves multiple saves that must all succeed or all fail — orders, payments, inventory, financial transactions.

Q21 Explain Django's Q objects and when to use them. Django ▼

Q objects allow complex queries with OR, AND, NOT logic. Chaining .filter() calls adds AND conditions. To use OR you need Q objects.

q_objects.py
from django.db.models import Q

# OR query — posts by user OR published
Post.objects.filter(Q(author=user) | Q(status='published'))

# AND with OR
Post.objects.filter(
    Q(title__icontains='django') | Q(body__icontains='django'),
    status='published'
)

# NOT
Post.objects.filter(~Q(status='draft'))

class PublishedManager(models.Manager):
    def get_queryset(self):

Q25 How does Django's F() expression work? Django ▼

F() expressions let you reference model field values in database operations without loading the object into Python. This avoids race conditions and is more efficient.

f_expression.py
from django.db.models import F

# BAD — race condition: read-modify-write
product = Product.objects.get(pk=1)
product.stock -= 1
product.save()

# GOOD — F() expression: atomic update in SQL
Product.objects.filter(pk=1).update(stock=F('stock') - 1)

# Comparing two fields
Post.objects.filter(views__gt=F('likes'))

Q31 How would you write custom Django middleware? Django ▼
middleware.py
import time

class RequestTimingMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response  # called once on startup

    def __call__(self, request):
        start = time.time()
        response = self.get_response(request)  # calls the view
        duration = time.time() - start
        response['X-Response-Time'] = f'{duration:.3f}s'
        return response

# Add to settings.py MIDDLEWARE list

Q33 How do you optimize Django for production? (Performance checklist) Django ▼

Q34 What is only() and defer() in Django QuerySets? Django ▼

Both limit which database columns are fetched. Use when you don't need all fields — saves memory and DB bandwidth.

only_defer.py
# only() — fetch ONLY these fields (defers everything else)
posts = Post.objects.only('id', 'title', 'created')

# defer() — fetch everything EXCEPT these fields
posts = Post.objects.defer('body')  # skip large text column

# values() — returns dicts instead of objects (fastest for read-only)
posts = Post.objects.values('id', 'title')
# [{'id': 1, 'title': 'Hello'}, ...]

Q36 What is Django Celery and when do you use it? Django ▼

Celery is an asynchronous task queue. Django views should respond in under 200ms. If a task takes longer (sending emails, resizing images, generating reports), offload it to Celery so the user isn't waiting.

tasks.py

from django.core.mail import send_mail

@shared_task
def send_welcome_email(user_id):
    user = User.objects.get(pk=user_id)
    send_mail('Welcome!', 'Thanks for joining.',
               'noreply@app.com', [user.email])

# In a view — non-blocking, returns immediately
send_welcome_email.delay(user.pk)

Q37 What is Django REST Framework (DRF) and why use it? DRF ▼

DRF is a toolkit for building Web APIs in Django. It provides serializers (convert data to/from JSON), authentication, permissions, viewsets, routers, and a browsable API interface. It's the industry standard for building REST APIs with Django.

  • Serialization — converts models to JSON and validates input
  • Authentication — JWT, Token, Session, OAuth2 support
  • Permissions — fine-grained access control
  • ViewSets + Routers — auto-generate URLs for CRUD endpoints
  • Browsable API — built-in HTML interface for testing
  • Filtering + Pagination — built-in support

Q38 What is a serializer in DRF? What does it do? DRF ▼

A serializer does two things: Serialization (Python object → JSON for API responses) and Deserialization (JSON → validated Python object for saving to DB). It also validates incoming data.

serializers.py
class PostSerializer(serializers.ModelSerializer):
    class Meta:
        model = Post
        fields = ['id', 'title', 'body', 'status', 'created']
        read_only_fields = ['id', 'created']

# Serialization (object → JSON)
serializer = PostSerializer(post)
data = serializer.data  # {'id': 1, 'title': 'Hello', ...}

# Deserialization (JSON → validated object)
serializer = PostSerializer(data=request.data)
if serializer.is_valid():
    post = serializer.save(author=request.user)

Q53 How do you override get_queryset() in a ViewSet and why? DRF ▼

Override get_queryset() to dynamically filter data based on the request — usually to implement data isolation (users only see their own data) or URL-based filtering.

class PostViewSet(viewsets.ModelViewSet):
    serializer_class = PostSerializer

    def get_queryset(self):
        user = self.request.user
        qs = Post.objects.select_related('author', 'category')

        # Staff sees all; regular users see only their own
        if not user.is_staff:
            qs = qs.filter(author=user)

        # Optional URL filter: /api/posts/?status=published
        status = self.request.query_params.get('status')
        if status:
            qs = qs.filter(status=status)

        return qs
Security critical: Always filter by ownership in get_queryset(). Returning all objects by default is a data leak vulnerability.

Q73 What is CORS and why does it block AJAX requests? AJAX ▼

CORS (Cross-Origin Resource Sharing) is a browser security mechanism that blocks JavaScript from making requests to a different origin (domain, protocol, or port) unless the server explicitly allows it.

  • Same origin: http://mysite.com → http://mysite.com/api ✓ (allowed)
  • Cross origin: http://mysite.com → http://api.other.com ✗ (blocked)

The server must respond with Access-Control-Allow-Origin: http://mysite.com (or *) in the response headers. In Django: install and configure django-cors-headers.

Important: CORS is a browser feature only. Postman, curl, and Python requests never get CORS errors. This is why your API works in Postman but fails in the browser.

Q75 Why does fetch() NOT throw errors for 404 or 500 responses? AJAX ▼

This is one of the most common interview gotchas. fetch() only rejects its Promise when there is a network failure (no internet, DNS error, request blocked). A 404 or 500 response from the server is still a "successful" HTTP communication, so fetch resolves.

error_handling.js
// WRONG — 404 will NOT go to .catch()
fetch('/api/post/99999/')
  .then(res => res.json())  // still runs even for 404!
  .catch(err => console.log(err)) // only fires for network errors

// CORRECT — always check response.ok
fetch('/api/post/99999/')
  .then(res => {
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
  })
  .catch(err => console.log(err)) // catches both HTTP + network errors

Q84 What is debouncing and how do you implement it for AJAX search? AJAX ▼

Debouncing delays execution until a user stops performing an action. For search, instead of making an AJAX call on every keystroke, you wait until the user stops typing for N milliseconds.

function debounce(fn, delay = 300) {
    let timer;
    return function(...args) {
        clearTimeout(timer);
        timer = setTimeout(() => fn(...args), delay);
    };
}

Q86 What is Promise.all() and when do you use it in AJAX? AJAX ▼

Promise.all() runs multiple promises simultaneously and waits for all of them to complete. Use it when requests are independent of each other — much faster than sequential awaits.

promise_all.js

    // const users = await fetch('/api/users/');
    // const posts = await fetch('/api/posts/');
    // const stats = await fetch('/api/stats/');

    // Parallel: max(300ms, 200ms, 150ms) = 300ms total

async function apiFetch(url, options = {}) {
    const token = localStorage.getItem('access_token');
    const res = await fetch(url, {
        ...options,
        headers: {
            'Content-Type': 'application/json',
            'Authorization': `Bearer ${token}`,
            ...options.headers
        }

            method: 'POST',
            headers: {'Content-Type': 'application/json'},
            body: JSON.stringify({refresh: localStorage.getItem('refresh_token')})

            const {access} = await refreshRes.json();
            localStorage.setItem('access_token', access);
            return apiFetch(url, options); // retry original request
        }
        window.location = '/login';
    }
    return res;
}

Q96 How do you implement AJAX with retry logic and exponential backoff? AJAX ▼
retry_fetch.js
async function fetchWithRetry(url, options = {}, maxRetries = 3) {
    for (let attempt = 0; attempt < maxRetries; attempt++) {
        try {
            const res = await fetch(url, options);
            if (!res.ok && res.status >= 500) {
                throw new Error(`Server error: ${res.status}`);
            }
            return res;
        } catch (err) {
            if (attempt === maxRetries - 1) throw err;
            const delay = 1000 * Math.pow(2, attempt); // 1s, 2s, 4s
            console.log(`Attempt ${attempt+1} failed. Retrying in ${delay}ms`);
            await new Promise(r => setTimeout(r, delay));
        }
    }
}

function uploadWithProgress(file, onProgress) {
    return new Promise((resolve, reject) => {
        const xhr = new XMLHttpRequest();
        const formData = new FormData();
        formData.append('file', file);

    });
}

Q100 What is a request interceptor pattern and how do you implement one? AJAX ▼

An interceptor is a wrapper that runs code before every request (add auth headers, logging) or after every response (error handling, token refresh). This is how Axios interceptors work internally.

const http = {
    request: async (url, options = {}) => {
        // REQUEST interceptor — runs before every call
        const token = getToken();
        const config = {
            ...options,
            headers: {
                'Content-Type': 'application/json',
                ...(token ? {'Authorization': `Bearer ${token}`} : {}),
                ...options.headers

        const response = await fetch(url, config);

        if (response.status === 401) await handleTokenRefresh();
        if (response.status === 403) redirectToForbidden();
        if (response.status >= 500) logServerError(url, response.status);

        return response;
    }
};
